# 已知限制与研究边界

这份文档记录当前实现中真实存在的边界、它们会怎样影响研究，以及可以采取的规避方式。它不是缺陷愿望清单；计划中的改进见 [路线图](roadmap.md)。

## 先说最重要的边界

ShowTime Atlas 帮助形成上下文，不替代史料批判。背景 CSV 是低密度研究定向层，推荐分是本地规则的匹配分，统计是事件记录的计数；三者都不表示史实可信度、历史重要性、活动强度或因果关系。

## 背景库

| 边界 | 影响 | 当前规避方式 |
| --- | --- | --- |
| 79 层接近通用研究骨架，但不是地区、群体或学科的完备集合 | 全球层较多；同一地区内部差异可能被宏区标签压平 | 查看覆盖矩阵；把内置层当方向参照，为具体课题另建主线或细分背景 |
| 单层通常只有 15–40 条宏观阶段 / 里程碑 | 不适合查某日发生的全部事件，也不会覆盖所有地方分期 | 精确事件放入专题 CSV；不要从“未出现”推断“未发生” |
| `# 来源框架` 是编纂框架摘要，不是逐条脚注 | 无法仅凭背景 CSV 完成来源复核 | 在正式研究中为关键事件补 sidecar 来源与项目参考资料 |
| 争议边界使用粗区间，历史名称采用便于比较的通行写法 | 可能掩盖不同学派、历法和政治命名争议 | 保留原始专题表述，在项目说明中记录采用的分期与异名 |
| 122 条持续阶段使用开区间；终点随运行年份变化 | 同一 CSV 在未来打开时聚合范围可能变长 | 可复现研究应把关键开区间改为明确终点，并在说明中记录快照日期 |

## 推荐器

| 边界 | 影响 | 当前规避方式 |
| --- | --- | --- |
| 推荐完全是本地启发式排序，不是语义模型 | 别名之外的隐喻、罕见异名和复杂跨语种关系可能漏报 | 检视四类理由；更新受控 `synonyms.json`；使用完整手动列表 |
| 专题范围按当前工作区所有图层的最早 / 最晚事件聚合 | 手动加入的超长背景层可能扩大后续推荐范围 | 在加入大尺度层前先查看推荐；必要时新建只含专题主线的工作区进行选层 |
| `≤100 年 → year`、`≥100 万年 → deep-time`，其余为 `mixed` | 阈值附近的项目可能与研究者主观尺度判断不同 | 把尺度理由视作排序依据而非分类结论；手动覆盖始终可用 |
| 地区从项目文本、图层名、事件标题和元数据中的受控别名推断 | 历史疆界、离散群体和同名地点可能误判；`global` 只是软对照 | 阅读区域理由，拒绝不合适候选；为专题补明确地点 / 标签 |
| 首次查看推荐会读取并解析全部本地背景 CSV | 在慢设备或高延迟静态主机上首次打开可能短暂停留在“建立索引” | 索引只在用户主动查看时建立并在本页缓存；手动加载不依赖它 |
| “暂不推荐”只保存在当前页面会话 | 刷新页面后忽略项会恢复 | 把拒绝当作本轮筛选；若需要长期记录，在项目说明中写明选层决策 |
| 匹配分不是概率或质量分 | 91 分不表示 91% 正确，也不评价背景层本身 | 只比较同一次候选排序，并以显示的时间 / 尺度 / 区域 / 标签理由作判断 |

无时间交集或 `year` 与 `deep-time` 直接悬殊的候选会被排除；索引失败的层不会被推荐，但仍可尝试手动加载。推荐从不自动改变工作区。

## 时间与 CSV

| 边界 | 影响 | 当前规避方式 |
| --- | --- | --- |
| BCE 支持年份与年份区间，不支持 `公元前221-01-01` 日期 | 古代研究不能用内置语法表达 BCE 月日 | 使用 BCE 年份 / 区间，并把更细历法信息写入标题或元数据 |
| `221 BCE` 内部映射为天文学年 `-220`，直接写 `-221` 则保留 `-221` | 混用两种写法可能产生一年偏差 | 同一项目统一计年约定；导入质检后检查范围 |
| 公元日期采用推算格里高利历数值，没有历法转换层 | 儒略历、地区历法和历史改历不会自动换算 | CSV 保存研究采用的规范日期，并在说明中记录原历法 |
| 反向区间会自动交换起止，开区间补到当前时间 | 原始语义错误可能被规范化后不易察觉 | 查看质检中的 `reversed_interval` / `open_interval` 提示 |
| 主 CSV 只支持单行记录，不支持带引号字段跨行 | 多段标题或说明不能直接放进 title | title 保持简短；长说明放入 `event_meta.json` |
| 主 CSV 导出重建事件行，不保留原文件注释和空行布局 | 用注释维护的编辑痕迹不会随图层导出 round-trip | 重要编纂说明写入项目 Markdown；背景库原文件继续在仓库维护 |
| 默认按 UTF-8 文本处理，没有编码选择器 | 旧式本地编码可能出现乱码 | 导入前转为 UTF-8 |

完整语法见 [CSV 格式与导入质检](CSV_FORMAT.md)。

## 项目包、元数据与兼容

- 不支持 ZIP64；导出使用未压缩 stored 条目，包体可能较大。超大资料应拆成多个项目，并保留原始文件备份。
- 无 Manifest 的旧 ZIP 最多导入前 100 个 CSV。正式大型项目应使用版本化 `00_manifest.json`。
- 高于当前支持主版本的 Manifest 会保守导入可识别 CSV，但不会猜测未知状态。
- sidecar 匹配有多个候选时会报告歧义，不会自动选择；这可能留下未应用元数据，但避免静默串错事件。
- 外部来源 URL 只做协议级安全过滤，不检查内容是否仍存在、可信或与事件相符。
- 项目没有加密、签名或权限系统。敏感项目包的存储、传输与访问控制由用户负责。

格式细节见 [项目包规范](PROJECT_FORMAT.md) 与 [事件元数据](METADATA.md)。

## 浏览器存储、分享与部署

- IndexedDB 是当前浏览器配置中的本地存储，不是云备份。清理站点数据、隐私模式、配额回收或设备故障都可能删除工作区；重要研究应定期导出 `.showtime.zip`。
- 存储容量、Canvas 最大尺寸和 Blob 下载上限取决于浏览器、操作系统与设备，应用无法给出统一上限。
- 本地项目的分享链接不包含原始数据；接收者必须先打开同一项目包。只有公开可访问项目 URL 才能随链接自动打开。
- 分享链接没有访问控制；项目 URL 本身若可公开访问，就应被视为公开资料。
- `file://` 不能可靠加载 ES modules 和本地 fetch。需要通过 `npm run dev`、GitHub Pages 或其他静态 HTTP 服务打开。
- 没有 service worker 或离线安装保证。页面和未缓存的背景文件需要静态站点可访问。
- 自动化质量门以真实 Chrome / Chromium 为主；其他现代浏览器通常可用，但下载、IndexedDB、触摸和字体排版尚无同等完整矩阵。

## Canvas、分析与可访问性

- 远景 LOD 会显示代表事件或时间箱聚合，不会在有限像素中绘制每条记录。放大、搜索或查看文本结果才能确认个别事件。
- 标签碰撞与极高密度数据会造成视觉省略；省略不是数据删除，导出项目和搜索仍使用完整事件集。
- 统计按导入的事件记录计算；来源较细的图层天然会比低密度背景层“更多”，不能据此比较真实历史活跃度。
- Canvas 提供键盘平移、缩放、探针和可访问名称，搜索 / 详情面板提供文本入口，但当前没有逐事件的完整屏幕阅读器 Canvas 镜像。
- 390 px 触屏已覆盖核心流程；更小屏幕、浏览器文本放大和非常长的图层名仍可能需要滚动或折叠面板。
- PNG 是当前视觉快照；SVG 是矢量输出，但都不替代含原始事件和元数据的项目包。

如果某项边界会改变研究结论，优先保留原始 CSV / 项目包、记录采用的分期与快照日期，并把可视化当作检索和比较界面，而不是最终证据。
